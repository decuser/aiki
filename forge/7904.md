# Thompson 7094 Implementation Cheat Sheet

## Scope

Implements only the IBM 7094 mechanisms required to execute the machine code generated by Ken Thompson's 1968 regular-expression compiler together with its published runtime routines. Unsupported machine facilities are not implemented. 

## Machine State

```text
memory   32,768 36-bit words
PC       15-bit instruction counter

AC       accumulator state required by CLA, CAL, ACL, PCA, PAC, SLW

XR1      15-bit index register
XR2      15-bit index register
XR4      15-bit index register
XR6      15-bit index register
XR7      15-bit index register
```

Unused:

```text
XR3
XR5
MQ
SI
I/O channels
device state
trap state
timing/overlap state
```

The 7094 has 32,768 words of 36-bit core memory and 15-bit addresses. 

## Word and Address Sizes

```text
WORD_BITS = 36
ADDR_BITS = 15

WORD_MASK = 2^36 - 1
ADDR_MASK = 2^15 - 1
```

Address and index arithmetic is reduced to 15 bits.

## Index Registers

The implementation uses normal seven-index-register mode.

```text
tag 0   no index register
tag 1   XR1
tag 2   XR2
tag 4   XR4
tag 6   XR6
tag 7   XR7
```

Tags 3 and 5 are unused.

Multiple-tag compatibility mode is not implemented. In normal 7094 mode, each nonzero tag identifies one index register. 

## Effective Address

For ordinary tagged instructions:

```text
EA = (Y - XR[tag]) mod 2^15
```

For tag 0:

```text
EA = Y
```

Index-register instructions use the tag to identify the index register being operated upon rather than to modify the instruction address. 

Indirect addressing is not implemented.

## Register Roles in Thompson's Runtime

```text
XR1   complement of current input character
XR2   control/list return index
XR4   subroutine return register
XR6   CLIST construction/copy index
XR7   NLIST construction/copy index
```

Thompson's runtime uses these registers directly in the published `CNODE`, `NNODE`, `FAIL`, and `XCHG` routines. 

# Instruction Set

## TRA — Transfer

```text
TRA Y[,T]
```

Effect:

```text
PC = EA
```

Example:

```text
TRA 2,4
```

If `XR4 = -x`, the effective address is:

```text
2 - (-x) = x + 2
```

This is used for subroutine return from `CNODE`. 

---

## TSX — Transfer and Set Index

```text
TSX Y,T
```

If the instruction is stored at address `x`:

```text
XR[T] = (-x) mod 2^15
PC    = Y
```

The selected index register receives the 2's complement of the address of the `TSX` instruction, then control transfers to `Y`.

Used for:

```text
TSX NNODE,4
TSX CNODE,4
TSX GETCHA,4
TSX CODE,2
TSX x,2
```



---

## TXL — Transfer on Index Low or Equal

```text
TXL Y,T,D
```

Effect:

```text
if XR[T] <= D
    PC = Y
else
    PC = PC + 1
```

XR is unchanged.

Used in character matching and list-copy termination.

---

## TXH — Transfer on Index High

```text
TXH Y,T,D
```

Effect:

```text
if XR[T] > D
    PC = Y
else
    PC = PC + 1
```

XR is unchanged.

Character matching uses:

```text
TXL FAIL,1,-'a'-1
TXH FAIL,1,-'a'
TSX NNODE,4
```

Only the encoded value corresponding to the desired character passes both tests. 

---

## TXI — Transfer with Index Incremented

```text
TXI Y,T,D
```

Effect:

```text
XR[T] = (XR[T] + D) mod 2^15
PC    = Y
```

Used for list traversal and construction:

```text
TXI *+1,7,-1
TXI *+1,7,1
TXI X1,6,-1
```



---

## AXC — Address to Index Complemented

```text
AXC Y,T
```

Effect:

```text
XR[T] = (-Y) mod 2^15
```

No memory operand is fetched.

Example:

```text
AXC 0,6
```

produces:

```text
XR6 = 0
```

Used to initialize CLIST indexing. 

---

## LAC — Load Complement of Address in Index

```text
LAC Y,T
```

Effect:

```text
XR[T] = (-address_field(memory[Y])) mod 2^15
```

The memory word is unchanged.

Example:

```text
LAC NNODE,7
```

loads the complement of the address field stored in the first instruction of `NNODE`. Thompson uses that address field as the NLIST count. 

---

## SCA — Store Complement of Index in Address

```text
SCA Y,T
```

Effect:

```text
address_field(memory[Y]) = (-XR[T]) mod 2^15
```

All other bits of the memory word remain unchanged.

With tag 0:

```text
address_field(memory[Y]) = 0
```

Examples:

```text
SCA CNODE,7
SCA CNODE,6
SCA NNODE,7
SCA NNODE,0
```

Code memory must therefore be writable. 

---

## PCA — Place Complement of Index in Accumulator

```text
PCA ,T
```

Effect:

```text
clear relevant AC word positions
AC[address field] = (-XR[T]) mod 2^15
```

Used to construct executable `TSX` instructions:

```text
PCA ,4
ACL TSXCMD
```



---

## PAC — Place Complement of Address in Index

```text
PAC ,T
```

Effect:

```text
XR[T] = (-AC[address field]) mod 2^15
```

AC is unchanged.

Thompson uses:

```text
TSX GETCHA,4
PAC ,1
```

`GETCHA` returns the next character right-adjusted in AC, so `PAC ,1` places its complement in XR1. 

---

## CLA — Clear and Add

```text
CLA Y[,T]
```

Effect required by this implementation:

```text
AC = ordinary 36-bit representation of memory[EA]
```

Positions P and Q are cleared according to the 7094 definition.

Used to load the constant:

```text
TRACMD  TRA XCHG
```

before storing it at the end of CLIST. 

---

## CAL — Clear and Add Logical Word

```text
CAL Y[,T]
```

Effect required by this implementation:

```text
AC logical word = complete 36-bit memory[EA]
```

The memory sign bit maps into the logical AC position P.

Used when copying executable instruction words:

```text
CAL NLIST,7
SLW CLIST,6
```



---

## ACL — Add and Carry Logical Word

```text
ACL Y[,T]
```

Performs 36-bit logical addition over the AC logical word and the addressed memory word, including end-around carry.

Required effect:

```text
AC.logical = logical_add_with_end_around_carry(
    AC.logical,
    memory[EA]
)
```

Used to construct `TSX x+1,2` from:

```text
PCA ,4
ACL TSXCMD
```

where:

```text
TSXCMD  TSX 1,2
```



---

## SLW — Store Logical Word

```text
SLW Y[,T]
```

Effect:

```text
memory[EA] = AC logical 36-bit word
```

AC is unchanged.

Used to write executable instructions into CLIST and NLIST:

```text
SLW CLIST+1,7
SLW CLIST,7
SLW NLIST,7
SLW CLIST,6
```



# Runtime Memory Structures

## CODE

Contains generated regex machine instructions.

Example generated program for:

```text
a(b|c)*d
```

occupies offsets `0..22`. 

## CLIST

Contains executable instructions of the form:

```text
TSX address,2
```

terminated by:

```text
TRA XCHG
```

Each `TSX` represents a currently viable continuation. 

## NLIST

Contains executable instructions of the form:

```text
TSX address,2
```

These identify CODE locations to be considered for the next input character. 

## CNODE

A call from location `x`:

```text
TSX CNODE,4
```

causes:

```text
TSX x+1,2
```

to be inserted into CLIST and execution to resume at:

```text
x+2
```

The branch at `x+1` is deferred; the branch at `x+2` is followed immediately. 

## NNODE

A call from location `x`:

```text
TSX NNODE,4
```

causes:

```text
TSX x+1,2
```

to be inserted into NLIST.

Execution then returns to the next entry in CLIST. 

## FAIL

```text
FAIL  TRA 1,2
```

Transfers to the next entry in CLIST. 

## XCHG

Responsibilities:

```text
copy NLIST to CLIST
append TRA XCHG
reset runtime list counters
obtain next character
place complement of character in XR1
start a fresh search at CODE
execute CLIST
```

Published sequence:

```text
XCHG   LAC NNODE,7
       AXC 0,6
X1     TXL X2,7,0
       TXI *+1,7,1
       CAL NLIST,7
       SLW CLIST,6
       TXI X1,6,-1
X2     CLA TRACMD
       SLW CLIST,6
       SCA CNODE,6
       SCA NNODE,0
       TSX GETCHA,4
       PAC ,1
       TSX CODE,2
       TRA CLIST
```



## INIT

```text
INIT   SCA NNODE,0
       TRA XCHG
```

Initializes the NLIST count and enters the normal XCHG cycle. 

# Host Services

## GETCHA

Not emulated as 7094 I/O.

Required contract:

```text
obtain next input character
place it right-adjusted in AC
recognize end of input
terminate search at EOF
```



## FOUND

Application-specific service invoked whenever the complete regular expression has matched.

The implementation may record or report the match.

Thompson specifies a one-character delay between the end of a match and transfer to `FOUND`. An additional EOF character must therefore be processed to obtain complete results.

# Execution Rule

For each supported instruction:

```text
fetch memory[PC]
decode supported opcode and fields
advance or replace PC according to instruction semantics
apply only the required memory/register effects
reject unsupported instructions
```

Unsupported opcode behavior:

```text
machine error: unsupported instruction
```

# Implementation Criterion

The implementation is correct when Thompson's published generated code and runtime produce the required changes to:

```text
memory
PC
AC
XR1
XR2
XR4
XR6
XR7
```

for each executed instruction and reproduce the published regex search behavior.
